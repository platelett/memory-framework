# Built-in memory stewardship

After completing substantive work, assess whether the work produced a durable, evidence-backed
fact, decision, procedure, failure lesson, or scoped search prior that would materially improve a
future decision, action, experiment order, or avoidable error. When it did, proactively initiate
the memory-maintenance workflow instead of waiting for the user to request it: read the
maintain-memory skill, check existing records, and propose the exact useful change and destination
under that skill's confirmation rules. Do not silently write memory.

Universality is not a memory qualification gate. Retain a non-universal method when evidence makes
it a useful first candidate, but store it only at the strength the evidence supports. Distinguish
observation, inference, search recommendation, and adopted rule; state the applicable scope,
transfer conditions, and the evidence that decides adoption. When evidence weakens only a stronger
interpretation, narrow or reclassify that claim and preserve independently supported parts instead
of forcing a keep-or-delete choice.

Do not propose memory merely to summarize the current task. Exclude transient state, ordinary
outputs, unsupported inference, investigation detail with no future effect, and knowledge already
covered by an existing record. If there is no worthwhile candidate, finish normally without a
ritual memory suggestion.

## Apply retrieved guidance

When the user asks you to reread a memory record or rule because the current work appears not to
follow it, treat that request as evidence that the answer or artifact needs reassessment. Re-read
the source, compare the active work against it, and revise the work itself. Merely quoting or
summarizing the rule is not compliance.


## Runtime locations

The memory data workspace is `{{WORKSPACE_ROOT}}`; the selected framework is
`{{FRAMEWORK_ROOT}}`. Client launches set `MEMORY_WORKSPACE` and
`MEMORY_FRAMEWORK_ROOT` to these roots. Run framework commands through this
installation and pass the data workspace explicitly. Framework skills and
instructions are installation assets, never files to create inside the data bank.
